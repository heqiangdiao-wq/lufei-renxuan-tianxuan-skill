## 背景：目标是什么

《人选天选论》没有正式出版实体书，是**网络连载**（序 + 七章），作者同时通过
**直播连麦**大量答疑。内容分散在三类形态里：

| 形态 | 在哪 | 价值 |
|---|---|---|
| **文字稿** | 作者连载 + 粉丝站整理 | 体系骨架、定稿术语 |
| **作者原声** | B站官方号章节视频 | 定稿理论的口头版 |
| **直播连麦 / 切片** | 抖音（20+ 个切片号）、B站直播录像 | 他**实际怎么回答别人问题**——血肉 |

核心论点一句话：**人选祸，天选福；人选福，天选祸。**

目标产物是一个**能按他的框架回答问题的 AI 技能**，且要求
「尽量贴近原作者表达」，因此语料必须**分层保存**：

| 层 | 内容 | 决定什么 |
|---|---|---|
| L1 | 理论骨架（章节结构） | 答得**对不对** |
| L2 | 概念词典（天权 / 道痕 / 捞石头 / 河流世界…） | 术语**准不准** |
| L3 | 问答索引（原话 + 时间戳 + 出处） | 可**追溯** |
| L4 | 人格风格（口癖、语气） | **像不像** |

**关键结论：前两层决定「对不对」，后两层决定「像不像」，混存必废。**

## 为什么不收录素材

三类风险，逐条说清楚：

### 1. 版权 —— 素材不是我们的

- **书稿**：作者在抖音以图片版连载，粉丝站做了全文整理。**「公开发表」不等于「授权转载分发」**，
  粉丝站的转载也不能作为已授权的依据。
- **音频 / 转录全文**：同样属于他人作品。把完整转录 JSONL 公开，等同于分发全文。
- 标题、ID、时长这类**事实性元数据**风险较低，但正文不行。

### 2. 安全 —— 采集脚本里带登录态

抖音的用户主页接口对未登录访客不返回数据，因此「按号抓全集」必须使用登录态。
本项目用**独立浏览器 profile**存放 cookie（`state/dy_profile/`，实测 359MB）。

⚠️ **这是账号凭证，推送到公开仓库等于交出你的账号。已在 `.gitignore` 中永久排除。**

### 3. 体量 —— 不适合进 git

```
corpus/audio/        1.3 GB   原始音频
state/dy_profile/    359 MB   浏览器 profile
_probe/models/       214 MB   whisper 模型权重
```

即使不考虑版权，这些也不该进 git 历史（会让仓库永久膨胀）。

### 那怎么做成「能供给别人用」的形态？

想开源给他人使用，合理的切法是：

| 内容 | 去向 |
|---|---|
| 脚本 + 方法论 + `SKILL.md` | ✅ 本仓库 |
| 结构化**索引**（视频 ID / 标题 / 时长 / 链接 / 标签） | ✅ 可公开，**但不含正文** |
| 每条观点的**短引用** + 指向原视频的**时间戳** | ✅ 可公开（引用范畴） |
| 书全文、音频、完整转录 JSONL | ❌ 仅本地私有 |

## 数据流水线

两条链路，能力不同：

```
B站（零风控，可全自动）
  视频清单 → 查重 → yt-dlp 只取音频轨 → 本地转录 → 登记

抖音（有频控，需登录态 + 低频）
  主页/相关推荐发现 ID → 查重 → Playwright 开详情页
  → 拦 aweme/detail → 取播放地址 → 下 mp4 → ffmpeg 抽音轨 → 本地转录 → 登记
```

**共用后处理**（两个平台产物统一）：

```
转录 JSON（带时间戳、无标点）
  → ① 合并片段、保留时间边界
  → ② 术语校正（terms.yaml，只换字）
  → ③ 补标点断句（只加标点，不改字）
  → ④ 来源标注（作者原声 / 第三方解读 + book_ref）
  → ⑤ 内容去重（n-gram，删冗余重复、标记片段归属）
  → ⑥ 结构化条目 → 干净文字稿 .md + corpus.jsonl
```

### 处理边界（重要设计原则）

**只做三件事：纠错字、补标点、标来源。**
绝不改写、不摘要、不润色、不跨来源合并 —— 他的口癖和语气就是「像不像」的关键，一改写就废。

每条同时保留两列，任何修改可回溯：

```json
{
  "id": "bilibili-BV1DpbC67ELK-0002",
  "source": {"platform": "bilibili", "author": "自己造船的路飞",
             "origin": "author_voice"},
  "time": {"start": 20.0, "end": 41.0},
  "raw":   "...实现报复报效国家...",
  "clean": "...实现抱负报效国家...",
  "corrections": [{"from": "报复", "to": "抱负", "confidence": "verified"}],
  "book_ref": "第一章·河流世界"
}
```

`origin` 字段是关键：**它保证不会把别人的解读当成作者原话讲出去。**

## 快速开始

### 依赖

```
Python 3.12+        # 推荐隔离 venv
ffmpeg              # 抽音轨 / 切段
yt-dlp              # B站下载（抖音不支持，其签名算法已失效）
faster-whisper      # 本地转录，CPU int8 可跑，无需 GPU
playwright          # 抖音采集
```

### 工具路径

脚本**优先从 PATH 查找** `ffmpeg` / `ffprobe` / `yt-dlp`；
找不到才回退到内置默认路径（开发机的隔离环境路径 `C:\Users\PC\.workbuddy\...`）。

> 所以：把 `ffmpeg`、`yt-dlp` 放进 PATH 就**不用改任何代码**；
> 否则请修改对应脚本顶部的常量（`collect.py` / `collect_douyin.py` / `transcribe.py`）。

备份目录默认取「项目上一级 `_lufei_backup`」，可用环境变量 `LUFEI_BACKUP` 覆盖。

### 克隆与配置

```bash
git clone <repo>
cd lufei-renxuan-tianxuan-skill

# 按需创建这些目录（不进版本控制）
mkdir -p corpus/{audio,transcripts,processed,clean,book} state
```

### B站采集（最简单，无需登录）

```bash
# 建清单：每行一个链接
echo "https://www.bilibili.com/video/BV1xxxxxxx" > state/links_bilibili.txt

python scripts/collect.py --links state/links_bilibili.txt
python scripts/process.py     # 清洗
python scripts/export.py      # 导出干净文字稿
```

### 抖音采集（需扫码）

```bash
python scripts/login_douyin.py           # 弹独立浏览器窗口，用手机扫码
python scripts/discover_user_page.py \
       --uid-file state/real_uids.txt    # 抓号的作品列表（格式：sec_uid TAB 号名）
python scripts/collect_douyin.py \
       --ids-file state/douyin_long_ids.txt --limit 5 --gap-min 20 --gap-max 45
```

### 术语校正表

`state/terms.yaml` 是**纠错的核心**，需要你自己积累。它同时要处理两类问题：

1. **ASR 同音错字** —— 语音模型没见过专有名词，会按发音猜常见字
2. **源文本自带错字** —— 粉丝整理稿可能有系统性用字错误

```yaml
core_terms:
  - correct: 贪婪
    wrong: [贪梦, 贪蓝]
    confidence: verified
```

## 踩过的坑

这些是实际调试出来的，每一条都曾卡住整条流水线：

### 1. 抖音 `sec_uid` 截断会伪装成「风控」

用正则从页面 HTML 里抠 `sec_uid` 会**被截断**。抖音拿到无效 ID 就返回**空壳页**：
页面能打开、URL 正常、`/aweme/post/` 请求 0 次、标题是空的「的抖音」。

**症状和风控长得一模一样**，导致误判「抖音封了主页接口」，白排查一整天。
（headless / 有头 / 复用 cookie 三种配置都试过，全都「失败」——因为根本不是风控问题。）

✅ **正确做法**：完整 `sec_uid` 只能从**视频元数据**的 `author.sec_uid` 取。

### 2. 抖音是 DASH：视频轨和音频轨分开

`video.bit_rate[]` 里全是**纯视频轨**，`-vn` 抽出来是空的，ffmpeg 报
`Output file does not contain any stream`。

音频轨在 `bit_rate_audio` 里 —— **有元数据（大小、码率）却没有下载地址**。

✅ **解法**：用顶层 `play_addr`（音视频合一），下完整视频后本地抽音轨。
⚠️ 且**绝不能**用 `music.play_url` —— 那是背景音乐，不是人声。

### 3. faster-whisper 对长音频会一次性申请巨量内存

对整段音频做 STFT，160 分钟音频需要连续分配 **2.76 GiB**：

```
numpy._ArrayMemoryError: Unable to allocate 2.76 GiB
for an array with shape (1, 920973, 201)
```

崩溃得很快（约 2 分钟），容易被误判成「限流」。

✅ **解法**：把 ffmpeg 输出**管道流式**喂给转写，按块处理，**完全不产生临时文件**。
（早期版本先切片到磁盘、转完再删 —— 反而触发了第 4 条的守卫陷阱。）

### 4. 沙盒的「安全删除守卫」会杀掉进程

某些环境下，`os.remove` / `shutil.rmtree` 会被安全守卫拦截，并且**直接终结 python 进程**
（退出码 1，不留 traceback）。表现为「跑到一半什么都没发生」，极难排查。

✅ **解法**：① 尽量不产生临时文件；② 必须清理时用**截断为 0 字节**代替删除。

### 5. HuggingFace 缓存在 Windows 上可能退化成空文件

`~/.cache/huggingface/hub/models--X/snapshots/{commit}/model.bin` 变成 **0 字节**，
但 `blobs/` 下的真实文件是完整的 —— 符号链接没建成功。

于是模型「有目录没内容」，加载必失败——**降级链路会因此断掉**。

✅ **解法**：从 `blobs/` 复制真实文件到 `snapshots/`。
⚠️ LFS 文件要用 tree json 里的 **`lfs_sha256`** 字段定位 blob，`blob_id` 只是 LFS 指针。

### 6. 并行跑两个转录会互相挤崩

内存紧张时（实测 15.7GB 机器上只剩 1.5GB），两个转录进程会抢内存导致子进程被杀。
同时开 Playwright 抓取抢 CPU 也会触发。

✅ **解法**：串行；并给采集脚本加**内存门控**（不足时等待或跳过，而不是崩）。

### 7. 多进程同时写同一个登记表会丢数据

两个采集进程各写各的，后写的覆盖先写的 —— 实测丢了 18 条记录。

文件锁在 Windows 上容易互相等死。✅ **解法**：**按平台分文件**
（`registry.bilibili.jsonl` / `registry.douyin.jsonl`），读取时合并，写入各管各的。

### 8. 转录文稿标点全靠猜，要按停顿切

Whisper 的分段点本身就是语音停顿，**上一段的 `end` 等于下一段的 `start`**，
所以按「间隔多大才加逗号」判断，结果永远是 0，输出会是几百字一坨没有标点。

✅ **解法**：每个片段后**必补逗号**，再按长停顿断句。

### 9. 纯字符串替换会误伤

术语校正表把「味**道跟**那个不一样」错改成「味**道痕**那个不一样」——
`道跟` 跨了两个词（味道 + 跟）。

✅ **解法**：高置信度词才自动替换；有歧义的标注为 `guess` 并交人工确认。

### 10. 术语表键名不一致会造成「静默失效」

`terms.yaml` 的顶层键写成 `terms:`，而代码读 `core_terms` ——
**yaml 解析成功、不抛异常**，于是连 fallback 的文本解析都不触发，
结果**载入 0 条、错字一个不修**，而日志里只多了一行 `[术语表] 载入 0 条`，混在几十行输出中根本看不出来。

实测影响面：14,698 条条目里 **150 处错字漏修**，其中作者名字「路飞」
被 ASR 写成「陆菲 / 陆飞 / 路非」共 **116 处** —— 也就是语料里主角名字全是错的。

✅ **修法**：兼容多种键名；**载入后校验条数不为 0，0 条即报警**。

**这条的教训比修法更重要**：这类 bug 不会让程序崩溃，只会让产物悄悄变脏 ——
比崩溃更危险，因为不报错就不会有人去查。
凡是「载入配置」和「键名映射」（yaml 键 / API 字段 / 列名）的地方，都是静默失效的高发区。
